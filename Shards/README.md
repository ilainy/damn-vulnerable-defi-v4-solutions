# Shards

## 一、题目简介

本题是典型的**整数下溢+零成本资产获取**高危业务逻辑漏洞场景，核心为支持NFT碎片拆分交易的去中心化NFT交易市场。平台允许NFT持有者将完整NFT拆分为海量ERC1155碎片（Shards）对外售卖，买家可按需购买碎片，集齐全部碎片后可赎回原始NFT，仅当NFT完全售罄后卖家才可结算收款。

合约核心规则：市场对每笔NFT售卖订单收取**1% DVT手续费**，手续费可存入链上金库并参与质押生息；买家可通过fill函数购买NFT碎片，支持分批认购，未完全售罄的订单支持买家在指定窗口期取消购买并退款。平台依赖定点除法运算计算用户应付金额，默认数学运算逻辑严谨、资产交易无套利空间。

看似无漏洞的交易结算逻辑，因**mulDivDown向下取整导致整数下溢**，攻击者可实现零成本无限购买NFT碎片，配合取消订单退款机制无限刷取平台DVT资金，最终掏空市场全部资产。

基础环境参数：

- 市场初始资产：存有手续费累积的大量 DVT 代币

- 在售订单：单份NFT拆分为 10000000000000000000000000 碎片，售价 1000000 USDC

- 定价机制：通过USDC单价、DVT汇率、碎片总量动态计算单份碎片购买成本

- 用户初始资产：玩家初始持有 0 DVT，无任何可交易资产

解题目标：在**单次交易**内尽可能多的盗取市场DVT资产，满足资金流失阈值校验，并将所有追回资产转入指定recovery回收账户，且不影响质押合约资金余额。

## 二、审计视角

### 1\. 核心高危漏洞：定点除法向下取整引发零成本套利

合约`fill`购买碎片的核心计价逻辑存在致命整数下溢漏洞，用户应付金额计算公式为：`want.mulDivDown(_toDVT(offer.price, _currentRate), offer.totalShards)`。合约采用**mulDivDown向下取整**定点运算，在题目固定参数下，单次购买少量碎片（≤133）时，分子数值远小于分母，运算结果直接向下取整为0。

这意味着攻击者可以**0 DVT成本免费购买NFT碎片**，合约无任何扣费拦截、无余额校验、无交易风控，直接完成碎片确权，形成无成本资产获取漏洞。

### 2\. 退款机制无成本套利闭环

平台`cancel`取消订单逻辑存在严重风控缺失：用户取消购买订单时，合约会按照**历史购买汇率、真实碎片数量**计算退款金额，全额返还DVT代币。攻击者免费购入碎片后，在可取消窗口期内撤销订单，无需付出任何成本，即可套现等值DVT，形成「零成本购碎片→撤销订单→套现资金」的完整套利闭环。

### 3\. 单次交易限制绕过缺陷

题目强制要求玩家仅执行一次链上交易，但合约未限制**单次交易内的调用频次**。攻击者可通过外部攻击合约，在单笔玩家交易中循环执行上千次购币、撤单操作，批量刷取海量DVT，完美绕过交易次数限制，满足通关条件。

### 4\. 业务风控全面缺失

合约交易体系无任何兜底风控：无最小购买数量限制、无单次交易金额阈值、无高频调用熔断、无盈亏校验、无异常交易拦截。完全依赖数学运算保证交易公平性，忽略定点除法的下溢特性，导致整个资产结算体系彻底失效。

## 三、开发者默认安全假设

1\. **数学运算绝对可信**：盲目信任Solidity定点除法运算逻辑，默认所有购买行为都会产生有效扣费，忽略向下取整导致的零金额交易场景。

2\. **交易行为合规可控**：默认用户均为正常交易者，只会大额批量购买碎片，不会利用小额订单触发整数下溢漏洞。

3\. **单次交易无批量攻击风险**：仅限制外部交易次数，未预判单次交易内部可循环调用恶意逻辑，忽视合约嵌套调用的攻击风险。

4\. **退款逻辑绝对公平**：默认用户购买资产均付出对应成本，未校验购买时的真实扣费金额，直接无条件退款。

## 四、同类项目审计点

1\. **定点除法运算重点校验**：所有使用`mulDivDown`向下取整的资产结算、计价、分账逻辑，必须校验小额参数下的零值运算场景，防止整数下溢套利。

2\. **扣费前置校验机制**：任何资产扣费逻辑，必须前置校验计算结果是否为0，禁止零成本获取平台资产。

3\. **退款溯源校验**：退款、回撤资金逻辑必须溯源校验用户原始支付金额，禁止无成本全额退款。

4\. **单次交易行为风控**：针对有交易次数限制的场景，需同步限制单次交易内的高频循环调用，封堵批量套利入口。

5\. **小额交易阈值限制**：碎片化资产交易、分批认购场景，必须设置最小购买数量、最小交易金额，规避数学运算漏洞。

## 五、完整解题思路

1\. **定位漏洞参数**：测算得出单次购买100个碎片可稳定触发整数下溢，应付金额为0，实现零成本购币。

2\. **搭建攻击合约**：基于单次交易限制，编写外部攻击合约，将批量套利逻辑封装，保证玩家仅发起一次链上交易。

3\. **批量零成本套利**：循环执行fill函数免费购买NFT碎片，再调用cancel函数撤销订单，批量刷取平台DVT代币。

4\. **满足通关阈值**：通过10001次循环套利，使平台流失资金超过初始资产的0\.01%，通过系统校验阈值。

5\. **归集盗取资产**：将攻击合约套利所得的全部DVT代币，统一转入指定recovery回收账户，完成通关。

## 六、报错复盘

### 报错1：Marketplace still has tokens 资金流失阈值不达标

**报错原因**：循环套利次数不足，10000次循环刷取的资金量刚好低于系统0.01%的流失阈值，无法通过严格大于校验。

**解决方案**：将循环次数调整为10001次，小幅增加套利总量，精准跨过通关阈值。

### 报错2：玩家交易Nonce超限

**报错原因**：直接在测试函数内编写循环逻辑，每一次fill、cancel都会消耗玩家交易次数，导致nonce不为1，违反单次交易规则。

**解决方案**：将所有循环套利逻辑封装至外部攻击合约，玩家仅调用一次攻击合约，保证nonce=1。

### 报错3：编译缺失库文件

**报错原因**：多余引入项目未配置的数学库，导致合约编译失败。

**解决方案**：删除无关库依赖，攻击逻辑仅调用合约原生方法，无需额外第三方库。

```solidity
// 外部攻击合约：封装批量套利逻辑，保证玩家仅一次交易
contract Exploit {
    ShardsNFTMarketplace public marketplace;
    DamnValuableToken public token;
    address recovery;

    constructor(ShardsNFTMarketplace _marketplace, DamnValuableToken _token, address _recovery) {
        marketplace = _marketplace;
        token = _token;
        recovery = _recovery;
    }

    function attack(uint64 offerId) external {
        // 单次购买100碎片，触发mulDivDown下溢，扣费为0
        uint256 wantShards = 100;
        // 10001次循环，达标阈值
        for (uint256 i = 0; i < 10001; i++) {
            marketplace.fill(offerId, wantShards);
            marketplace.cancel(offerId, i);
        }
        // 归集全部套利资金至回收账户
        token.transfer(recovery, token.balanceOf(address(this)));
    }
}

```

## 八、合约修复方案

1\. **增加零扣费交易拦截**：在fill购币逻辑中，前置校验应付金额，若计算结果为0则直接 revert，禁止零成本获取资产。

2\. **设置最小交易阈值**：配置NFT碎片最小购买数量，杜绝小额参数触发整数下溢的套利场景。

3\. **退款金额溯源校验**：cancel退款时，读取用户原始支付金额，仅退回用户实际付出的DVT，杜绝无成本套利。

4\. **增加单次调用频次限制**：限制单用户、单笔交易内的fill/cancel调用次数，防止批量循环套利。

5\. **优化运算逻辑**：将向下取整的mulDivDown替换为向上取整运算，或增加数值兜底校验，规避整数下溢风险。

## 九、漏洞总结

Shards题目的核心漏洞是**整数定点运算下溢+退款逻辑无溯源校验**形成的闭环套利漏洞。开发者过度依赖数学运算的安全性，未针对向下取整特性做兜底风控，导致小额购买可零成本获取平台资产，搭配无条件退款机制，攻击者可无限刷取合约资金。

这题暴露了DeFi交易系统的安全误区：一是将数学运算逻辑等同于业务风控，缺失人工兜底校验；二是只限制外部交易次数，忽略内部嵌套循环调用的攻击风险；三是退款、结算等核心资金逻辑未做溯源校验，极易引发资产套利漏洞。此类整数运算套利漏洞广泛存在于分片交易、分批认购、资金分账类合约中，是智能合约审计的重点盯防场景。
